# Flow room post v1

Op: `sink.room.post`. Capability: `flow-room-post/v1` in core's manifest provides.
Only the attested `reserved:basal` carrier may send the op. The stamp uses the
same `flow_id`, `flow_version`, and `code_hash` fields as `sink.board`.

`vectors.json` contains request/reply pairs generated by the real dispatch and
SQLite store path in `room_post_wire_vectors_are_generated_by_dispatch_and_pinned`.
Each case starts with a fresh store unless its precondition says otherwise.
The base fixture has approved flow `flow-x` version 1 (hash: 64 zeroes), agent
audience `ag_test`, and sink
`{"kind":"room","room_id":"rm_fleet","mentions":["ag_other","ag_test"]}`.
Room `rm_fleet` (#fleet-notices) has members TEST (`ag_test`) and OTHER
(`ag_other`), two initial events, and no live sessions. Core's clock is 100 ms.
The `principal` field documents carrier attestation, not a body field Basal sends.
Replies wrap the management result or ErrorBody, not a complete transport envelope.
Rate-limit `error.detail.retry_after_ms` is a relative delay. Storage failures
use the board sink's `sink_store_failed` shape. All other errors are final.

The pinning test compares freshly generated bytes and checks SHA-256 for both
files. To regenerate, set `UPDATE_FLOW_ROOM_POST_VECTORS=1` when running that test.
All files are UTF-8 with a final LF; `SHA256SUMS` excludes itself.
