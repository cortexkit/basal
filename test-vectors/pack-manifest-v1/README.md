# Pack manifest v1

Each JSON file contains a complete `flow.json` as `manifest` and basal's exact
`flow.install` refusal as `reply.error`, generated through the real intake path.
Pack runtime is pending: the valid manifest is recognized but cannot be installed
or dry-run yet. No ability call, destination binding or provider lookup runs.

- `valid-pack.json`: two abilities (calendar and reminders), room, agent inbox
  and notice destinations; `pack_runtime_unavailable` after static validation.
- `net-fetch.json`: an ability together with `net.fetch` is forbidden.
- `literal-grant.json`: packs cannot also grant literal `ops` (or `sinks`).
- `bad-key.json`: an ability key fails the lowercase key grammar.
- `bad-token.json`: a capability token has a zero major version.
- `duplicate-key.json`: two abilities use the same key.
- `empty-scope.json`: an ability has no scope keys.
- `too-many.json`: more than 16 abilities.
- `unknown-kind.json`: an unrecognized destination kind.
- `notice-without-severity-max.json`: notice requires a severity ceiling.
- `severity-max-on-room.json`: other destination kinds refuse that ceiling.
- `urgent-severity.json`: notice cannot grant urgent severity.
- `unknown-ability-member.json`: ability entries refuse unknown fields.

All manifests include the required `explanation`. Shape refusals name the exact
field path and use the existing `install_refused` family. Named pack refusals
keep their own codes. The same test also checks fresh dry-run refusal paths.

Regenerate on Linux, then rerun without the environment variable to check drift:

```sh
BASAL_WRITE_VECTORS=1 RUST_TEST_THREADS=1 cargo test --locked -p basal-module --test pack_manifest pack_manifest_vectors
```

Files are UTF-8 with a final LF. `SHA256SUMS` covers this README and every JSON
sample, excluding itself. The test compares generated bytes, not just hashes of
the files already on disk.
