# Git directory pinning and indirection controls

## Scope

The Unix runner executes `git -C .` after `fchdir` to the directory opened and
verified by the filesystem built-in. Filesystem authorization and Windows
execution are unchanged. Approved-root symlinks keep filesystem-compatible
semantics. The host still calls `Grant::checked_roots` before authorizing and
executing a call: roots generated by flow templates must remain inside their
recorded `under` bounds and retain their recorded canonical path.

Indirection containment is preflight-only: gitdir, commondir and recursive
alternates must resolve inside approved git roots when checked, but are not
frozen through Git's reads. `docs/builtins.md` explains that residual boundary.

## Mutation witnesses

`rustc 1.99.0 (b940084d7 2026-09-28)` and Cargo 1.99.0. Each run used:

```
cargo test -p basal-host --locked --lib builtins::git::tests::repository::<test> -- --exact
```

Each exact run executed one test, returned 101, and failed only its named test.
Other tests were filtered out; no broad-suite mutation claim is made. The
catalogue keeps five shared-callsite rows on Linux, plus one separate macOS
verified-open-helper row. Shared-callsite macOS runs are evidence, not extra CI
rows. Each row uses `select = "expected"`. The macOS command-path edit was also proved by
`ckdev-mutate 0.10.0`; its CAUGHT report is `git-held-directory-macos.json` (that
proof's temporary macOS catalogue row was removed to avoid duplicate shards).

The CI platform fence now has a two-file basal-host allowlist for macOS-only
whole-function edit anchors. Shared Unix edits in those files and all other
basal-host files still belong on Linux. Regression tests check that boundary.

The unmutated repository tests also cover normal reads, symlinked approved
roots, relative and separately approved gitdir targets, relative/quoted and
separately approved alternates, and a linked worktree's common object store.
The race hook is compiled only under `cfg(test)` and uses channels to pause
between verified opening and execution, without changing the parent's cwd.
