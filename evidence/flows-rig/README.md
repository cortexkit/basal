## Package lifecycle

Each cycle registers immutable package bytes, checks idempotence and conflicting-byte/foreign-agent refusals, references the exact version in the private persona, fetches and approves the cingulate card containing the exact script, manifest and capability rows, waits for core's committed approval through `persona.check`, then pins and flushes. Core confirms a real `flow.instance.ensure`; basal holds the independently derived BLAKE3 instance ID and stable owning agent. All three documented ID vectors are pinned independently in the rig tests.

Scheduled activation returns `self = {agent_id: ...}` and both `$self` / `self.agent_id` sinks carry that stable ID. Core's receipts and digest store confirm the writes. Unpinning marks the instance removed without changing whether it is enabled, who disabled it, the recorded reason, or the disable timestamp.

The stale-generation case is explicitly a seeded fixture, not a captured wire reply. With isolated basal stopped, the package/agent counter advances from 2 to **1002**. Core next sends an ensure with a smaller counter, which basal refuses without clearing the removed mark or changing the enabled switch. `persona.check` exposes core's new durable counter as exactly **1002**, with its pending-operation marker cleared and no retry loop. Core learns that distinctive value from the stale refusal's `detail.current`. In this generation case core's store is only observed, never seeded. Both successful modes observed the exact floor.

A corrective ensure restores the same instance, and a fresh scheduled run proves it is active before revocation. Core grants package-administration operator authority to the session recorded as its primary board. Cingulate instead permits consent answers from the daemon-attested callosum module using a phone-class bind. The rig uses each API's own authorization, without injecting caller claims.
